# 시장놀이 게임 PRD

## 1. 문서 목적

이 문서는 시장놀이형 웹게임의 MVP(최소 기능 제품) 구현 명세다. 핵심 게임 기능은 **자원 모으기**와 **시장 물품 구매·판매**이며, 이를 이용하기 위한 마을 지도 이동, 장소 상호작용, 가방 UI를 포함한다. 개발자는 이 문서의 화면, 규칙, 데이터, API, 검증 조건과 완료 기준을 따라 기능을 구현할 수 있어야 한다.

> 개정된 허브·시장 마을·작업 지도 흐름을 프론트엔드에 구현했다. 클릭 목적지 이동, 가게/작업 구역 진입 시 전체 화면 전환, 가방 HUD를 포함한다. 프로토타입은 브라우저 `localStorage`를 사용하며, 서버·PostgreSQL 백엔드는 아직 연결하지 않았다.

## 0. 실행 방법 및 현재 구현 상태

### 실행 방법

프로젝트 폴더에서 `index.html`을 최신 데스크톱 또는 모바일 브라우저로 열면 플레이할 수 있다. 별도의 빌드나 패키지 설치는 필요하지 않다. Google Fonts를 사용할 수 없는 환경에서는 시스템 기본 글꼴로 표시된다.

### API 필요 여부 및 GitHub Pages 배포

현재 MVP는 로그인, 여러 기기 간 저장 동기화, 서버 검증이 없고 브라우저 `localStorage`에만 게임 데이터를 저장하므로 별도 API 서버가 필요하지 않다. 이 저장 방식은 같은 브라우저/기기 안에서만 유지된다. 계정, 클라우드 저장, 서버 기준 거래 검증을 추가할 때만 PRD의 백엔드 API와 데이터베이스를 구현한다.

GitHub Actions 배포 워크플로는 `master`에 push되면 GitHub Pages를 활성화하고 정적 사이트를 배포한다. Pages 자동 활성화 권한이 없는 경우 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 한 번 설정한다. 배포 완료 URL은 Actions 실행 결과 또는 Pages 설정에서 확인한다. 앱 파일은 상대 경로를 사용하므로 저장소 이름이 포함된 Pages URL에서도 동작한다.

### 구현된 기능

- 연한 녹색 마을 테마와 오리지널 판다 캐릭터가 있는 반응형 웹 화면
- 양털 깎기, 밭 가꾸기, 과일 채집, 나무 채집, 낚시
- 전 활동 공통 5초 작업 타이머, 활동당 1개 진행, 고정 보상
- 가방의 아이템 수량과 현금 표시
- 아이템별 고정 가격을 사용한 시장 구매·판매
- 생산·구매·판매 내역 표시
- 브라우저 새로고침 후 작업·가방·현금·거래 내역 복원
- 마우스/터치로 길 위 목적지를 클릭해 이동, 이동 팻말 클릭 시 장면 전환
- 시장 지도 건물 클릭 후 개별 상점 화면, 작업 지도 구역 클릭 후 확대 작업 화면
- 채소·과일, 물고기, 장작, 털의 네 건물별 구매·판매
- 모든 화면 오른쪽 위의 가방 아이콘, 현금·아이템·최근 활동 패널

### 프로토타입의 저장 범위

현재 데이터는 브라우저의 `localStorage`에 저장된다. 따라서 같은 브라우저와 기기에서는 상태가 유지되지만, 다른 기기와 동기화되지는 않으며 서버 검증도 제공하지 않는다. 실제 서비스 전환 시 이 PRD의 API·DB 명세에 따라 백엔드를 연결해야 한다.

## 2. 제품 개요

- **장르:** 간단한 생활·경제 게임
- **플랫폼:** 웹 브라우저
- **주요 플레이 흐름:** 시작 마을 → 시장 또는 일하기 팻말 선택 → 해당 장면으로 전체 화면 전환 → 건물/작업 구역 선택 → 물품 구매·판매 또는 자원 생산
- **플레이어 수:** 1인
- **게임 언어:** 한국어
- **시작 화면:** 여러 건물 가운데 길 위에 판다가 서 있고, 양옆에 시장/일하기 이동 팻말이 있다.
- **이동:** 판다는 마우스로 클릭한 길 위 목적지까지 연결된 길을 따라 걷는다. 모바일에서는 탭한 목적지를 사용한다. 키보드/WASD 이동은 사용하지 않는다.
- **화면 이동:** 이동 팻말을 누르면 모달이나 스크롤 변화가 아니라 화면 전체가 새 장면으로 바뀐다. 가방 HUD는 계속 보인다.

### 2.1 제품 목표

1. 플레이어가 여러 생산 활동으로 자원을 반복해서 얻을 수 있다.
2. 얻은 자원과 현금이 가방·시장 화면에 정확히 반영된다.
3. 고정된 가격으로 아이템을 사고팔 수 있다.
4. 새로고침 후에도 진행 중인 작업, 가방, 현금이 복구된다.

- 밭 가꾸기(작물 생산)

- 나무 채집
- 낚시
- 공통 작업 타이머
- 아이템 보상과 인벤토리 저장
- 시장 상품·가격 조회
- 아이템 구매와 판매
- 현금 잔액 및 거래 내역 저장
- 마을 지도와 모든 길에서의 캐릭터 이동
- 시장/작업 장소 팻말 및 작업 장소 클릭 상호작용
- 카테고리별 가게와 가게별 상품 목록
- 시작 마을, 시장 마을, 작업 지도, 확대 작업 화면 간 전체 화면 전환

- 모든 페이지에서 접근 가능한 가방 및 현금 UI

### 3.2 제외 범위

아래 기능은 이번 MVP에서 구현하지 않는다.

- 도구의 종류나 성능, 도구 내구도
- 체력, 피로도, 에너지
- 씨앗, 미끼, 연료 등 소모품
- 자원 고갈, 장소별 재고, 자원 재생성
- 작물 성장 단계, 양의 개체 상태, 낚시 반응 미니게임
- 랜덤 보상, 희귀 아이템, 품질 등급
- 전투, 퀘스트, 레벨, 랭킹
- 집 꾸미기, 제작, 요리, 옷 만들기
- 플레이어 간 거래, 멀티플레이, 은행

## 4. 용어

| 용어 | 정의 |
|---|---|
| 활동(Activity) | 양털 깎기, 농사, 채집, 낚시 중 하나의 생산 행동 |
| 작업 세션(Activity Session) | 활동을 시작한 시각과 완료 여부를 기록하는 데이터 |
| 보상(Reward) | 작업 완료 시 인벤토리에 추가되는 아이템과 수량 |
| 인벤토리(Inventory) | 플레이어가 보유한 아이템별 수량 |
| 마을 지도(Village Map) | 길, 팻말, 시장, 작업 장소를 배치한 탐색 화면 |
| 장면(Scene) | 시작 마을, 시장 마을, 작업 지도, 세부 작업 화면 등 전체 화면 단위 |
| 목적지 이동(Click-to-move) | 길 위나 건물/구역을 클릭하면 캐릭터가 연결된 길을 따라 목적지까지 이동하는 조작 |
| 작업 장소(Work Location) | 양 우리, 밭, 나무 구역, 연못 등 생산 활동이 가능한 지도 위치 |
| 가게(Store) | 시장에서 상품 카테고리별로 구매·판매하는 화면 |
| 가방 HUD | 모든 페이지에서 현금과 보유 아이템을 확인할 수 있는 고정 UI |
| 현금(Cash) | 시장 구매에 사용하고 판매로 얻는 정수 단위의 게임 머니(원) |
| 거래(Transaction) | 아이템 구매 또는 판매 내역 |

## 5. 공통 게임 규칙

1. 모든 활동의 작업 시간은 **5초(5,000ms)**로 동일하다.
2. 플레이어는 동시에 하나의 작업만 진행할 수 있다.
3. 생산 자원은 무한하다. 활동을 반복해도 자원이나 장소가 고갈되지 않는다.
4. 도구, 체력, 소모품 보유 여부는 작업 조건에 포함하지 않는다.
5. 활동별 보상은 고정 수량이다. MVP에서는 랜덤 보상을 지급하지 않는다.
6. 작업 완료 시 현금이 아니라 아이템을 지급한다.
7. 아이템을 시장에 판매했을 때만 현금이 증가한다.
8. 구매·판매 가격은 서버의 아이템 카탈로그가 기준이다. 클라이언트가 보낸 가격은 사용하지 않는다.
9. 시장의 판매 재고는 무한하다. 구매 가능 여부는 플레이어의 현금으로만 결정한다.
10. 모든 수량은 0 이상의 정수, 모든 금액은 0 이상의 정수로 처리한다.
11. 판다는 시작 마을, 시장 마을, 작업 지도에 표시된 모든 연결된 길에서 이동할 수 있다. 각 장면의 길 네트워크 밖으로는 이동할 수 없다.
12. 이동은 마우스 클릭 또는 터치 탭으로 목적지를 선택하는 방식이다. 키보드 방향키/WASD 이동은 제공하지 않는다.
13. 팻말을 누르면 즉시 해당 장면으로 전환한다. 건물/작업 구역을 누르면 판다가 길을 따라 입구까지 이동한 후 해당 가게/세부 작업 화면으로 전환한다.
14. 이동 거리와 시간은 생산 보상·거래·활동 가능 여부에 영향을 주지 않는다.

### 5.1 마을 지도와 캐릭터 이동

- 지도 장면 ID는 `hub`, `market_map`, `work_map`이다. 세 장면은 별도의 전체 화면이며 각각 독립된 길 지도와 캐릭터 위치를 가진다.
- 새 플레이어는 `hub` 장면의 중앙 길에 생성된 판다와 함께 시작한다. 중앙 주변에 여러 마을 건물을 배치하고, 길 좌우에 「시장」·「일하기」 팻말을 둔다.
- 지도 디자인은 첨부 참고 이미지의 다채로운 어린이용 마을/건물 배치와 구역 구분을 참고하되, 캐릭터·배경·건물 그래픽은 게임에 맞는 오리지널 에셋으로 구성한다.
- 각 지도 좌표계는 기준 `1200 × 800`으로 하고 SVG `viewBox` 또는 동등한 반응형 좌표계를 사용한다. 지도는 작은 화면에도 전체 경로가 보이도록 축소/확대한다.
- 플레이어가 도로 위의 지점을 클릭/탭하면 클릭 지점에 목적지 표식을 표시하고, 판다가 길 네트워크를 따라 가장 짧은 경로로 걸어간다. 클릭 지점이 도로 밖이면 가장 가까운 접근 가능한 도로 지점으로 보정한다.
- 모든 장면의 길 그래프는 교차점과 연결된 도로 선분으로 정의한다. 장면에 그려진 모든 도로 선분이 시작점에서 도달 가능해야 한다.
- 캐릭터는 길 밖, 건물 내부, 장식물, 물가 등 통행 불가 영역을 통과하지 않는다. 판다의 발밑 기준점으로 충돌을 판정한다.
- 목적지를 다시 클릭하면 현재 경로를 취소하고 새 목적지로 경로를 다시 계산한다. 클릭 가능한 건물/구역을 누르면 일반 목적지 이동 대신 해당 입구를 목적지로 설정한다.
- 이동은 마우스 왼쪽 클릭/터치 탭으로만 조작한다. 키보드 이동, 방향 패드, 드래그 이동은 제공하지 않는다.
- 기준 지도에서 걷는 속도는 초당 180 좌표 단위로 한다. 이동은 돈·체력·아이템을 소모하지 않는다.
- 판다는 이동 방향을 바라보고, 이동 중 간단한 걷기 모션을 표시한다. 이동이 끝나면 대기 모션으로 돌아온다.
- 팻말의 클릭 영역은 팻말 전체로 한다. 팻말 클릭 시 캐릭터가 걸어갈 필요 없이 즉시 해당 전체 화면 장면으로 전환한다.
- 저장된 위치는 `map_id`별로 보관한다. 다시 장면에 들어오면 해당 장면의 마지막 유효한 길 위치에서 시작한다. 저장 위치가 없거나 잘못된 경우 그 장면의 기본 진입 위치를 사용한다.
- 각 장면에 「이전 화면」/「마을로」 이동 버튼을 두며, 복귀 시 이전 지도 위치를 복원한다.

## 6. 자원 모으기 기능

### 6.1 활동 및 보상 명세

| 활동 ID | 화면 표시명 | 획득 아이템 ID | 획득 아이템명 | 1회 수량 | 작업 시간 |
|---|---|---|---|---:|---:|
| `shearing` | 양털 깎기 | `wool` | 양털 | 2 | 5초 |
| `farming` | 밭 가꾸기 | `barley` | 보리 | 3 | 5초 |
| `fruit_gathering` | 과일 채집 | `apple` | 사과 | 2 | 5초 |
| `wood_gathering` | 나무 채집 | `wood` | 나무 | 1 | 5초 |
| `fishing` | 낚시 | `carp` | 붕어 | 1 | 5초 |

수량은 초기 밸런스용 기본값이다. 구현에서는 코드 여러 곳에 흩어 쓰지 않고 활동 설정 데이터에서 관리한다.

### 6.2 사용자 흐름

1. 플레이어가 허브에서 「일하기」 팻말을 클릭한다.
2. 현재 허브 화면 전체가 작업 지도(`work_map`) 화면으로 전환된다.
3. 양 우리, 밭, 나무 구역, 연못 중 하나를 마우스/터치로 클릭한다.
4. 판다가 작업 지도 길을 따라 해당 구역의 입구까지 자동으로 걷는다.
5. 도착하면 현재 화면이 해당 구역의 확대 작업 장면으로 전환된다.
6. 작업 장면에서 제공되는 생산 행동을 선택한다. 나무 구역에는 과일 채집과 나무 채집이 모두 표시된다.
7. 활동명, 1회 보상, 작업 시간(5초)을 확인하고 **일하기**를 누른다.
8. 서버가 활동 ID와 진행 중 작업 여부를 검증하고 작업 세션을 생성한다.
9. 작업 장면에 5초 타이머가 표시되고, 완료 후 보상 아이템이 인벤토리에 추가된다.
10. 완료 결과와 갱신된 가방 HUD를 표시한다. 플레이어는 작업 지도로 돌아가 다른 구역을 선택하거나 작업을 반복한다.

### 6.2.1 작업 장소 배치와 상호작용

| 장소 ID | 장면 | 지도 위치 | 장소 오브젝트 | 활동 |
|---|---|---|---|---|
| `sheep_pen` | `work_map` | 왼쪽 아래 | 양 우리와 양 | 양털 깎기 |
| `field` | `work_map` | 오른쪽 아래 | 밭 | 밭 가꾸기 |
| `grove` | `work_map` | 오른쪽 위 | 나무 구역 | 과일 채집, 나무 채집 |
| `pond` | `work_map` | 가운데 아래 | 연못 | 낚시 |

- 작업 지도는 전체 화면이며 양 우리·밭·나무 구역·연못을 서로 다른 색/배경/울타리 등으로 가시적으로 구분한다.
- 구역 클릭 시 판다가 길을 따라 입구까지 걷고, 도착 후 해당 구역만 크게 보이는 별도 작업 장면으로 전환한다. 위치 클릭만으로 보상을 지급하지 않는다.
- 나무 구역 확대 화면에서는 `과일 채집`과 `나무 채집`을 독립된 행동으로 제공한다.
- 상세 작업 화면에는 작업 장소와 액션 버튼이 표시되고, 뒤로 가기 버튼은 작업 지도 화면으로 돌아간다.
- 작업을 시작한 후에는 화면을 이동해도 하나의 작업 세션과 타이머가 유지된다. 다른 활동은 현재 작업 완료 전까지 시작할 수 없다.

### 6.3 작업 상태와 시간 처리

작업 세션은 `active` 또는 `completed` 상태를 갖는다.

- 작업 시간 판정은 브라우저 타이머가 아니라 **서버가 기록한 시작 시각**을 기준으로 한다.
- 클라이언트 타이머는 진행 상황 표시용이다.
- 5초가 지나기 전에 완료 요청이 도착하면 보상을 주지 않고 `WORK_NOT_FINISHED` 오류를 반환한다.
- 플레이어가 새로고침하면 서버에서 활성 세션을 조회하고 남은 시간을 다시 표시한다.
- 작업 중 브라우저를 닫아도 세션은 유지된다. 5초가 지난 뒤 다시 접속하면 완료 요청을 할 수 있다.
- 완료된 세션은 다시 완료할 수 없다. 중복 요청으로 보상이 중복 지급되어서는 안 된다.
- 작업 취소 기능은 MVP에 포함하지 않는다.

### 6.4 인벤토리 반영

- 완료된 작업의 보상 아이템을 플레이어 인벤토리에 추가한다.
- 해당 아이템이 기존에 있으면 수량을 더하고, 없으면 새 인벤토리 항목을 생성한다.
- 수집 결과는 `gather` 유형의 아이템 기록으로 저장한다.
- 인벤토리 변경과 세션 완료 처리는 데이터베이스 트랜잭션으로 수행한다. 하나만 저장되고 다른 하나는 실패하는 상태를 허용하지 않는다.

## 7. 사고팔기 기능

### 7.1 시장 가게·상품·초기 가격

시장 팻말을 누르면 시작 마을에서 시장 마을로 **전체 화면 전환**한다. 시장은 카테고리 버튼 목록이 아니라 길과 연결된 여러 채색 건물로 표현한다. 건물은 도로 양쪽에 독립적으로 배치하고, 각 건물까지 길을 따라 이동할 수 있어야 한다.

| 가게 ID | 건물/가게 표시명 | 시장 지도 배치 | 포함 아이템 |
|---|---|---|---|
| `produce` | 채소·과일 가게 | 시장길 왼쪽 | 보리, 사과 |
| `fish` | 물고기 가게 | 시장길 왼쪽 또는 안쪽 골목 | 붕어 |
| `firewood` | 장작 가게 | 시장길 오른쪽 | 나무 |
| `wool` | 털 가게 | 시장길 오른쪽 또는 안쪽 골목 | 양털 |

시장 화면에서도 판다는 마우스/터치로 클릭한 길 위 목적지까지 이동한다. 건물 클릭 시 해당 건물의 입구까지 걸어간 뒤 **개별 가게 전체 화면**을 연다. 각 가게는 해당 카테고리의 상품만 보여준다. 구매 기능과 기존 판매 기능을 모두 유지하며, 판매는 가게에 속한 아이템만 판매할 수 있다.

| 아이템 ID | 화면 표시명 | 가게 | 구매가 | 판매가 | 구매 가능 | 판매 가능 |
|---|---|---|---:|---:|---|---|
| `wool` | 양털 | 털 가게 | 15원 | 10원 | 예 | 예 |
| `barley` | 보리 | 채소·과일 가게 | 8원 | 5원 | 예 | 예 |
| `apple` | 사과 | 채소·과일 가게 | 8원 | 5원 | 예 | 예 |
| `wood` | 나무 | 장작 가게 | 12원 | 8원 | 예 | 예 |
| `carp` | 붕어 | 물고기 가게 | 20원 | 14원 | 예 | 예 |

가격은 초기 제안값이다. 실제 구현에서는 데이터베이스의 아이템 카탈로그를 기준으로 사용한다. 판매가를 구매가보다 낮게 설정하여 구매·판매 반복만으로 현금이 증가하지 않도록 한다.

### 7.1.1 시장 사용자 흐름

1. 플레이어가 허브의 「시장」 팻말을 클릭한다.
2. 허브가 사라지고 길 양쪽의 가게 건물과 도로가 있는 시장 지도 화면으로 전환된다.
3. 플레이어가 길을 클릭해 이동하거나 특정 건물을 클릭한다.
4. 건물을 클릭하면 판다가 해당 건물 입구로 이동한 뒤 그 가게의 상품 화면으로 전체 전환된다.
5. 상품 카드에서 구매 또는 판매 수량을 선택한다.
6. 서버가 거래를 검증하고 결과를 저장한다.
7. 거래 후 현금, 인벤토리, 상단 가방 HUD와 상품 화면을 갱신한다.
8. 가게의 「시장으로」 버튼은 시장 지도, 「마을로」 버튼은 시작 허브로 돌아간다. 복귀 시 각 지도에서 저장된 캐릭터 위치를 복원한다.

### 7.2 구매 처리

1. 가게 목록에서 카테고리를 선택하고, 해당 가게에서 아이템과 구매 수량을 선택한다.
2. 총액은 `서버 구매가 × 요청 수량`으로 계산한다.
3. 서버가 플레이어의 현금, 아이템 구매 가능 여부, 수량을 검증한다.
4. 현금을 총액만큼 차감한다.
5. 인벤토리에 구매 수량을 추가한다.
6. 구매 거래 내역을 저장한다.
7. 새 현금과 인벤토리를 반환해 화면을 갱신한다.

현금 차감, 인벤토리 추가, 거래 내역 저장은 하나의 데이터베이스 트랜잭션으로 처리한다.

### 7.3 판매 처리

1. 해당 아이템을 취급하는 가게에 들어가 판매 수량을 선택한다. 가방 HUD에서 아이템의 「가게에서 판매」 버튼을 누르면 해당 가게를 바로 연다.
2. 총액은 `서버 판매가 × 요청 수량`으로 계산한다.
3. 서버가 플레이어의 인벤토리 수량, 아이템 판매 가능 여부, 요청 수량을 검증한다.
4. 인벤토리에서 판매 수량을 차감한다.
5. 현금에 총액을 더한다.
6. 판매 거래 내역을 저장한다.
7. 새 현금과 인벤토리를 반환해 화면을 갱신한다.

인벤토리 차감, 현금 증가, 거래 내역 저장은 하나의 데이터베이스 트랜잭션으로 처리한다.

### 7.4 거래 검증 및 오류

| 조건 | 응답/화면 처리 |
|---|---|
| 아이템 ID가 없음 | `ITEM_NOT_FOUND`, 거래하지 않음 |
| 상품이 구매 불가 | `ITEM_NOT_BUYABLE`, 거래하지 않음 |
| 상품이 판매 불가 | `ITEM_NOT_SELLABLE`, 거래하지 않음 |
| 수량이 0, 음수 또는 정수가 아님 | `INVALID_QUANTITY`, 거래하지 않음 |
| 구매 현금 부족 | `INSUFFICIENT_CASH`, 필요한 금액과 보유 현금 표시 |
| 판매 보유량 부족 | `INSUFFICIENT_ITEMS`, 판매하지 않음 |
| 가격이 요청에 포함되거나 조작됨 | 클라이언트 가격을 무시하고 서버 가격 사용 |
| 요청 재전송 | 동일 거래가 중복 반영되지 않도록 요청 ID/멱등 키로 보호 |

거래 실패 시 현금, 인벤토리, 거래 내역은 모두 변경되지 않아야 한다.

## 8. 화면 명세

### 8.1 시작 허브 화면 (`hub`)

- 시작 화면은 참고 이미지 1처럼 여러 건물이 있는 마을 장면이다. 판다는 길 한가운데에 서 있고, 좌우에 화면 이동을 나타내는 팻말을 배치한다.
- 좌측 팻말은 「시장」, 우측 팻말은 「일하기」로 표시한다. 각 팻말은 고유한 클릭 영역을 가지며, 누르는 즉시 화면 전체를 해당 지도 장면으로 교체한다.
- 화면 전환은 팝업/모달/스크롤 이동이 아니다. 현재 지도의 건물·도로는 숨기고 목적지 지도를 전체 게임 영역에 표시한다. 전환 시 짧은 페이드 효과만 허용한다.
- 허브의 건물은 마을 분위기를 위한 배경이며, 구매/생산 기능은 이 화면에서 직접 시작하지 않는다. 이동 기능은 길 위 목적지 클릭, 주요 화면 이동은 좌우 팻말 클릭으로 한다.
- 첫 진입 시 판다는 허브 메인 길 중앙에서 시작한다. 허브로 돌아올 때는 마지막 허브 위치를 복원한다.

### 8.2 마우스/터치 클릭 이동

- 판다가 있는 지도에서는 길 위의 위치를 클릭/탭하면 해당 위치를 목적지로 삼는다.
- 판다는 현재 위치에서 목적지까지 도로 그래프의 최단 경로를 따라 자동으로 걷는다. 캐릭터를 드래그하거나 키보드로 이동시키지 않는다.
- 목적지에는 짧은 표시(예: 발자국/원형 마커)를 보여 이동 명령이 접수됐음을 알린다.
- 길이 아닌 곳을 클릭하면 가장 가까운 도달 가능한 도로 지점을 목적지로 보정한다. 캐릭터는 건물, 울타리, 장식, 물가를 통과하지 않는다.
- 이동 중 다른 길 지점을 클릭하면 기존 경로를 취소하고 새 목적지까지 다시 경로를 계산한다.
- 마우스/터치 클릭은 같은 동작으로 처리한다. 모바일 전용 방향 패드와 WASD/방향키 조작은 제공하지 않는다.

### 8.3 시장 마을 지도 (`market_map`)

- 「시장」 팻말을 누르면 전체 화면이 시장 마을 지도로 전환된다.
- 시장 마을은 참고 이미지 2처럼 길을 중심으로 양쪽에 실제 마을의 가게 건물들이 놓인 그림형 지도다. 기존의 카테고리 카드 나열 화면은 사용하지 않는다.
- 채소·과일, 물고기, 장작, 털 가게는 외관·간판·색을 달리해 한눈에 구별한다. 각 건물은 도로와 연결된 별도의 진입로와 입구 좌표를 가진다.
- 플레이어는 시장 지도 안의 모든 연결된 길을 클릭 이동으로 오갈 수 있다. 각 가게 입구까지 걸어갈 수 있어야 한다.
- 건물을 클릭하면 판다가 해당 건물의 입구까지 이동한다. 도착 후 지도 전체를 해당 가게의 상품 화면으로 전환한다.
- 시장 지도에서 「마을로」를 누르면 허브로 돌아간다. 가게 화면에서 「시장으로」는 시장 지도, 「마을로」는 허브로 돌아간다.

### 8.4 개별 가게 화면

- 한 화면에는 선택한 건물의 상품만 표시한다. 가격과 거래 규칙은 기존 시장 명세를 유지한다.
- 상품마다 아이콘, 이름, 현재 보유량, 구매가, 판매가, 구매 수량 입력/버튼, 판매 수량 입력/버튼을 제공한다.
- 구매 수량은 1 이상의 정수이며, 판매 수량은 1부터 현재 보유량까지의 정수다.
- 현금 부족 시 거래를 거절하고 필요한 금액과 보유 현금을 알린다. 보유량이 0이면 판매를 비활성화한다.
- 구매/판매 성공 뒤 현금, 보유 수량, 거래 내역 및 오른쪽 위 HUD를 즉시 갱신한다.

### 8.5 일하기 지도 (`work_map`)

- 허브의 「일하기」 팻말을 누르면 전체 화면이 작업 지도 페이지로 전환된다. 허브 장면에 구역 강조만 하는 방식은 사용하지 않는다.
- 참고 이미지 3처럼 작업 공간이 양 우리, 밭, 나무 구역, 연못으로 명확하게 나뉘어 보인다. 울타리, 지형, 작물, 양, 나무, 물 등 배경 오브젝트로 각 구역의 기능을 직관적으로 알린다.
- 구역의 위치는 표 6.2.1을 따른다. 각 구역에는 이름/행동 안내 표식을 두고 마우스·터치로 클릭 가능하게 한다.
- 플레이어는 작업 지도 내부의 모든 연결된 길을 클릭 이동으로 오갈 수 있다.
- 구역을 클릭하면 판다가 해당 구역 입구까지 이동하고, 도착 즉시 현재 작업 지도 전체를 그 구역에 초점을 맞춘 **확대 작업 장면**으로 전환한다. 팝업으로 겹쳐 띄우지 않는다.

### 8.6 확대 작업 장면

- 양 우리 확대 화면은 양과 양털 깎기 행동을, 밭 확대 화면은 밭 가꾸기를, 연못 확대 화면은 낚시를 시각적으로 보여준다.
- 나무 구역 확대 화면에는 과일 채집과 나무 채집 행동을 모두 표시한다.
- 각 행동 버튼에는 활동명, 보상 아이템/수량, 5초 작업 시간이 표시된다. 버튼을 눌러 생산을 시작하며, 타이머가 끝나면 지정 보상을 한 번 지급한다.
- 작업 완료 후 결과와 진행 상태를 보여준다. 「작업 지도로」 버튼은 work_map, 「마을로」는 hub로 돌아간다.
- 활성 작업은 다른 화면으로 이동하거나 가방을 열어도 진행된다. 동시에 하나의 작업만 진행 가능하다는 기존 규칙을 유지한다.

### 8.7 전 화면 공통 가방 HUD

- hub, market_map, 개별 가게, work_map, 확대 작업 화면 모두 오른쪽 위에 동일한 가방 아이콘과 현금 잔액을 고정한다.
- 가방 아이콘에는 보유 아이템 총수량 배지를 표시한다. 클릭/탭하면 현재 현금과 아이템별 보유 수량을 보여주는 패널을 연다.
- 소지품 패널에서 아이템의 「가게로 이동」을 누르면 관련 카테고리 가게 화면을 연다. 가게 화면에서는 해당 상품을 판매할 수 있다.
- 가방은 현재 보유 아이템을 보여준다. 구매 대기 장바구니는 이번 범위에 없다.
- 패널을 닫아도 현재 지도/가게/작업 장면, 캐릭터 위치, 진행 중 작업은 유지한다.

### 8.8 화면 전환과 알림

- 화면 흐름은 `hub → market_map → shop` 또는 `hub → work_map → work_area`다. 복귀 버튼은 각 경로의 이전 화면으로 이동한다.
- 팻말 클릭, 건물/구역 선택, 가게 진입/복귀는 화면 전체 장면 전환으로 표현한다. HUD만 전 장면에 공통으로 유지한다.
- 작업 시작/완료, 구매/판매 성공 및 실패는 한국어 토스트/상태 문구로 안내한다.
- 오류(잔액 부족, 보유량 부족, 네트워크 오류)는 현금·인벤토리를 변경하지 않고 이해하기 쉬운 문구로 표시한다.

## 10. API 명세

모든 API는 JSON을 사용한다. 플레이어 식별은 서버 세션 또는 인증된 사용자 정보로 처리하며, 클라이언트가 임의의 플레이어 ID를 지정해 다른 플레이어 데이터에 접근하지 못하게 한다.

### 게임 상태 조회

```http
GET /api/game-state
```

응답 예시:

```json
{
  "cash": 30,
  "currentScene": "hub",
  "characterPosition": { "mapId": "hub", "mapX": 0.5, "mapY": 0.5 },
  "inventory": [
    { "itemId": "wool", "name": "양털", "quantity": 2 }
  ],
  "activeActivity": null
}
```

### 활동 목록 조회

```http
GET /api/activities
```

활동 ID, 이름, 보상 아이템, 보상량, 작업 시간을 반환한다.

### 캐릭터 위치 저장

```http
PATCH /api/player/position
Content-Type: application/json
```

요청:

```json
{ "mapId": "market_map", "mapX": 0.5, "mapY": 0.5 }
```

화면 이동마다 요청하지 않는다. 이동을 멈춘 뒤 일정 시간(예: 1초) 동안 추가 이동이 없을 때 해당 `mapId`의 위치를 저장한다. 서버는 mapId, 좌표 범위, 해당 지도 보행 가능 영역을 확인한다. 위치 저장 실패는 자원·거래 기능을 중단시키지 않는다.

### 작업 시작

```http
POST /api/activities/start
Content-Type: application/json
```

요청:

```json
{ "activityId": "fishing" }
```

응답:

```json
{
  "sessionId": "uuid",
  "activityId": "fishing",
  "startedAt": "2026-11-13T10:00:00.000Z",
  "completesAt": "2026-11-13T10:00:05.000Z"
}
```

### 작업 완료

```http
POST /api/activities/complete
Content-Type: application/json
```

요청:

```json
{ "sessionId": "uuid", "requestId": "uuid" }
```

서버는 세션 소유자, 완료 여부, 서버 시간 기준 경과 시간, 활동 보상을 검증한다. 성공 응답에는 지급된 보상과 갱신된 인벤토리를 포함한다.

### 시장 상품 조회

```http
GET /api/market/categories
```

시장 가게 목록과 ID, 이름, 건물 외관 키, 지도 좌표 및 입구 좌표를 반환한다.

```http
GET /api/market/categories/{categoryId}/items
```

해당 가게에 속한 아이템 ID, 이름, 구매가, 판매가, 구매·판매 가능 여부를 반환한다. 가격을 프론트엔드 상수에만 두지 않는다.

시장 가게 목록 응답에는 카테고리 외에도 건물 외관 키, 건물 지도 좌표, 입구 좌표를 포함한다. 이를 사용해 시장 지도의 실제 건물과 클릭 후 이동 경로를 표시한다.

### 작업 장소 목록 조회

```http
GET /api/work-locations
```

양 우리, 밭, 나무 구역, 연못의 이름, 지도 좌표, 입구 좌표, 확대 작업 장면 키, 가능한 활동 목록을 반환한다.

### 구매

```http
POST /api/market/buy
Content-Type: application/json
```

요청:

```json
{ "categoryId": "produce", "itemId": "apple", "quantity": 2, "requestId": "uuid" }
```

서버는 아이템이 요청한 가게 카테고리에 속하는지 확인하고, 가격을 조회해 총액을 계산한 뒤 구매 가능 여부와 잔액을 검증한다.

### 판매

```http
POST /api/market/sell
Content-Type: application/json
```

요청:

```json
{ "categoryId": "wool", "itemId": "wool", "quantity": 2, "requestId": "uuid" }
```

서버는 아이템이 요청한 가게 카테고리에 속하는지 확인하고, 가격을 조회해 총액을 계산한 뒤 판매 가능 여부와 인벤토리 수량을 검증한다.

### 거래 내역 조회

```http
GET /api/market/transactions?limit=20&cursor=...
```

현재 플레이어의 구매·판매 기록을 최신순으로 반환한다. 다른 플레이어의 내역은 조회할 수 없다.

### 게임 활동 기록 조회

```http
GET /api/game-history?limit=20&cursor=...
```

`activity_events`의 생산 기록과 `transactions`의 구매·판매 기록을 시간 역순으로 합쳐 반환한다. 가방 패널의 최근 활동 내역에 사용한다.

## 11. 프론트엔드 구현 명세

- 화면은 `hub`, `market_map`, `shop`, `work_map`, `work_area` 장면 상태로 구성한다. 새로고침 후에는 허브부터 표시한다.
- 허브, 시장 지도, 작업 지도는 SVG/DOM 기반의 2D 지도 장면으로 구현한다. 건물·팻말·구역·길·캐릭터는 동일한 장면별 좌표계를 사용한다.
- 장면 간 전환은 전체 장면을 교체한다. 전환 시 HUD만 유지하고 이전 장면의 지도/콘텐츠는 숨긴다.
- 각 마을 지도에서 마우스 왼쪽 클릭/터치 탭으로 목적지를 정한다. 클릭한 도로 위치는 그 지점으로, 건물이나 작업 구역은 지정된 입구로 향하게 한다.
- 최단 경로 탐색은 해당 장면 도로 그래프의 교점/선분을 사용한다. 클릭한 목적지를 새로 바꾸면 진행 중 경로를 취소하고 다시 계산한다.
- 판다는 보행 가능 영역을 벗어나지 않으며 건물/울타리/물 등의 충돌을 처리한다. 장면에 그려진 모든 길이 서로 연결되고 걸을 수 있는지 테스트한다.
- 키보드 이동, 방향 패드, 드래그 이동은 제공하지 않는다. 터치 탭은 마우스 클릭과 같은 목적지 이동 동작이다.
- 시장 팻말은 `hub → market_map`, 일하기 팻말은 `hub → work_map` 전체 화면 전환을 수행한다.
- 시장 지도에서 건물 클릭 시 접근 지점까지 걷고 `shop` 장면으로 전환한다. 개별 가게 화면은 해당 카테고리 상품만 보여주며, 뒤로 가기는 시장 지도/허브로 이어진다.
- 작업 지도에서 구역 클릭 시 해당 입구까지 걷고 `work_area` 확대 장면으로 전환한다. 확대 장면에서 가능한 행동을 선택해 기존 5초 타이머 및 고정 보상 규칙을 실행한다.
- 가방 HUD는 모든 장면의 오른쪽 위에 표시한다. 클릭하면 현금·인벤토리 패널을 열고, 다시 클릭하거나 닫기 버튼으로 닫는다.
- 서버의 `GET /api/game-state` 응답을 초기 게임 상태로 사용한다. 프로토타입에서는 같은 상태 계약을 `localStorage`에서 복구할 수 있다.
- API 성공 응답을 기준으로 현금·아이템 상태를 갱신한다. 요청 전에 돈이나 아이템을 확정 변경하는 낙관적 갱신은 사용하지 않는다.
- 타이머는 `completesAt`과 현재 시각의 차이로 표시한다. 가방 열기와 전체 화면 전환 중에도 작업 진행 상태를 보존한다.
- 구매·판매 요청 중에는 해당 버튼을 비활성화해 우발적인 연속 클릭을 줄인다.
- 모든 API 오류는 한국어 메시지로 사용자에게 알려준다.
- 네트워크 재시도 시 동일한 `requestId`를 사용해 중복 보상/거래를 방지한다.

## 12. 백엔드 구현 명세

- **언어/런타임:** Node.js + TypeScript
- **HTTP 프레임워크:** Fastify(또는 프로젝트에서 합의한 동등 프레임워크)
- **DB:** PostgreSQL
- 모든 요청의 입력값과 플레이어 권한을 검증한다.
- 작업 완료 시 보상은 `activities` 설정에서 가져온다.
- 거래 가격은 `items` 테이블에서 가져오며 요청 본문의 가격은 무시한다.
- 현금과 인벤토리는 가능한 한 정수형으로 계산한다. DB 정수 범위를 초과하지 않도록 검증한다.
- `buy`, `sell`, `complete activity`의 여러 데이터 변경은 DB 트랜잭션으로 감싼다.
- `requestId`는 고유 제약으로 보호한다. 이미 처리된 요청이면 기존 결과를 반환하거나 중복 적용 없이 처리한다.
- 작업 시작은 플레이어별 활성 세션 고유성으로 동시 작업을 방지한다.

## 13. 권장 코드 구성

```text
index.html              # 지도, 시장, 가게, 가방 HUD의 앱 셸
styles.css              # 화면, 반응형 레이아웃, 지도 그래픽
game.js                 # 이동, 충돌, 장소 상호작용, 작업/거래 UI 상태
server/
  routes/                # HTTP 라우트
  services/              # 활동·시장 도메인 로직
  repositories/          # PostgreSQL 접근
  schemas/               # 요청/응답 검증 스키마
```

현재 프로토타입과 일치하도록 프론트엔드는 의존성 없는 HTML/CSS/JavaScript를 기준으로 한다. 지도 보행 가능 영역은 SVG 경로 또는 동등한 지도 충돌 형상으로 정의한다. 클라이언트와 서버 간 가격·보상 설정이 어긋나지 않도록 서버 설정을 기준으로 하며, 클라이언트는 조회 API에서 받은 설정을 화면 표시에 사용한다.

## 14. 비기능 요구사항

- 한 요청이 실패하면 현금, 인벤토리, 세션, 거래 내역이 부분적으로만 변경되지 않아야 한다.
- 작업 완료 요청을 여러 번 보내도 보상은 한 번만 지급한다.
- 거래 API를 재전송해도 같은 구매·판매가 중복 적용되지 않도록 한다.
- 현금, 수량, 가격은 음수가 될 수 없다.
- 브라우저 콘솔이 아닌 UI에도 오류 상태를 알기 쉽게 표시한다.
- 일반적인 데스크톱 브라우저에서 동작하고, 작은 화면에서도 주요 버튼과 숫자가 읽히도록 한다.
- 모든 지도 길을 마우스/터치 목적지 클릭으로 이동할 수 있어야 한다. 키보드 이동을 구현하지 않는다.
- 팻말/건물/작업 구역의 전체 화면 전환은 모바일과 데스크톱에서 일관되어야 하며, 공통 HUD와 진행 중 작업은 유지한다.
- 가방 HUD는 작업 장소/시장 하위 화면을 포함한 모든 화면에서 오른쪽 위에 유지한다. 작은 화면에서도 버튼이 콘텐츠에 가려지지 않는다.
- 시간은 서버에서 UTC로 저장하고 화면에 로컬 시간으로 표시한다.

## 15. 수용 기준 및 테스트 시나리오

### 장면 이동과 시작 허브

- [ ] 시작 화면에 여러 건물, 중앙 길 위 판다, 좌우 이동 팻말이 표시된다.
- [ ] 새 플레이어는 허브 중앙 길에서 시작한다.
- [ ] 「시장」 팻말 클릭 시 허브 요소가 사라지고 시장 건물 지도가 전체 화면으로 표시된다.
- [ ] 「일하기」 팻말 클릭 시 허브 요소가 사라지고 구역이 구분된 작업 지도가 전체 화면으로 표시된다.
- [ ] 화면 전환은 모달/오버레이가 아니라 화면 장면 교체이며, 가방 HUD는 그대로 보인다.
- [ ] 허브/시장 지도/작업 지도에서 도로 지점을 클릭하면 판다가 해당 목적지까지 걷는다.
- [ ] 모든 지도에 그려진 길, 샛길, 교차점의 모든 구간을 클릭 이동으로 오갈 수 있다.
- [ ] 연결된 도로의 각 구역은 고립되어 있지 않고, 모든 목적지에 길로 도달할 수 있다.
- [ ] 두 번째 목적지를 클릭하면 기존 경로를 취소하고 새 경로로 이동한다.
- [ ] 길 밖/건물/장식/물가를 클릭해도 가장 가까운 길로 보정되고 충돌 영역을 통과하지 않는다.
- [ ] 키보드/WASD 입력은 캐릭터 이동에 사용되지 않는다. 터치 탭은 마우스 클릭과 동일하게 동작한다.
- [ ] 새로고침 후 허브로 시작하며, 각 장면 재진입 시 그 장면의 마지막 유효 위치를 복원한다.

### 가방 HUD

- [ ] 마을, 작업 장소, 시장 목록, 모든 가게 화면에서 가방 아이콘이 오른쪽 위에 보인다.
- [ ] 아이콘을 클릭하면 현재 현금과 아이템별 보유 수량이 보인다.
- [ ] 생산·구매·판매 후 HUD의 금액과 수량이 즉시 갱신된다.
- [ ] 가방 패널을 닫아도 현재 화면과 진행 중 작업이 유지된다.
- [ ] 아이템의 「가게에서 판매」 동작은 해당 아이템을 취급하는 가게를 연다.

### 작업 지도와 확대 작업 장면

- [ ] 작업 지도가 양 우리(왼쪽 아래), 밭(오른쪽 아래), 나무 구역(오른쪽 위), 연못(가운데 아래)으로 시각적으로 구분된다.
- [ ] 작업 장소 클릭 시 판다가 길을 따라 해당 구역 입구까지 이동한다.
- [ ] 도착 후 작업 지도 위에 모달을 띄우는 대신 확대 작업 화면으로 전체 전환한다.
- [ ] 확대 화면별로 양털 깎기, 밭 가꾸기, 과일/나무 채집, 낚시의 행동이 올바르게 제공된다.
- [ ] 나무 구역에서는 과일 채집과 나무 채집이 각각 선택 가능하다.
- [ ] 뒤로 가기 버튼이 작업 지도와 허브의 지정 장면으로 돌아가며 위치를 복원한다.

### 자원 모으기

- [ ] 다섯 활동 모두 목록에 표시된다.
- [ ] 어느 활동을 선택해도 작업 시간이 5초로 표시된다.
- [ ] 한 플레이어가 동시에 두 작업을 시작할 수 없다.
- [ ] 작업 시작 후 5초가 지나기 전에 완료 요청하면 보상을 받지 않는다.
- [ ] 작업 완료 후 활동 표에 정의된 아이템과 수량이 정확히 추가된다.
- [ ] 같은 완료 요청을 반복해도 아이템이 중복 지급되지 않는다.
- [ ] 새로고침 후 활성 작업의 남은 시간 또는 완료 가능 상태가 복구된다.
- [ ] 생산을 여러 번 반복해도 자원 고갈이나 도구·체력·소모품 제한이 발생하지 않는다.

### 구매·판매

- [ ] 시장 지도는 카테고리 버튼이 아니라 도로 양쪽의 네 가게 건물로 표시된다.
- [ ] 네 건물은 도로와 연결되어 각 입구까지 클릭 이동으로 접근할 수 있다.
- [ ] 건물 클릭 후 입구까지 이동하고 해당 가게의 별도 전체 화면이 열린다.
- [ ] 채소·과일, 물고기, 장작, 털 가게 각각은 자신에게 배정된 상품만 표시한다.
- [ ] 구매·판매가와 기존 가격표가 각 가게에서 정확히 보인다.
- [ ] 가게에서 시장 지도와 허브로 각각 복귀할 수 있다.
- [ ] 현금이 충분한 구매는 현금이 감소하고 인벤토리가 증가한다.
- [ ] 현금이 부족한 구매는 아무 데이터도 변경하지 않는다.
- [ ] 보유량 이내의 판매는 인벤토리가 감소하고 현금이 증가한다.
- [ ] 보유량보다 많은 수량을 판매할 수 없다.
- [ ] 0, 음수, 소수, 문자열 수량은 거절된다.
- [ ] 클라이언트가 가격을 조작해도 서버 카탈로그 가격으로 거래된다.
- [ ] 거래 실패 시 현금·인벤토리·거래 내역이 모두 원상태다.
- [ ] 거래 요청 재전송으로 돈이나 아이템이 중복 변경되지 않는다.
- [ ] 새로고침 후 현금·인벤토리·거래 내역이 보존된다.

## 16. 구현 완료 정의

아래 조건을 모두 만족하면 MVP 구현이 완료된 것으로 본다.

1. 허브, 시장 지도, 작업 지도가 각각 별도 전체 화면으로 표시된다.
2. 판다가 시작 허브 중앙에서 시작하고, 마우스/터치 클릭으로 각 지도상의 모든 연결 도로를 이동한다.
3. 시장/일하기 팻말이 올바른 전체 화면 장면으로 이동시킨다.
4. 시장 지도에 도로 양옆의 네 가게 건물이 표시되고 건물별 화면으로 진입할 수 있다.
5. 작업 지도가 네 구역으로 구분되고, 구역 선택 후 확대 작업 화면으로 진입할 수 있다.
6. 다섯 가지 자원 모으기 활동이 같은 작업 시간과 명시된 고정 보상으로 동작한다.
7. 모든 화면의 오른쪽 위 가방 HUD에서 현금·보유 아이템을 확인할 수 있다.
8. 아이템이 인벤토리에 영속 저장되고 재접속 후 복구된다.
9. 가게에서 고정 가격으로 아이템 구매와 판매가 가능하다.
10. 구매·판매 가격을 서버가 결정하고 모든 잔액·수량을 검증한다.
11. 거래 내역이 영속 저장되며 중복 요청 및 부분 업데이트를 방지한다.
12. 본 문서의 수용 기준을 자동 또는 수동 테스트로 확인한다.
